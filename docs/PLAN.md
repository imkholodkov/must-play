## 1. Идея

Must Play — рейтинг игр Steam всех времён. Он помогает решить, во что поиграть.

- Единая оценка 0–100 для каждой игры. Складывается из оценок журналистов и голосов игроков.
- Пометка «спорная», если журналисты и игроки расходятся.
- Список must play, который сам обновляется при каждом пересчёте рейтинга.
- Рекомендации: похожие игры и подбор по жанру, платформе, языку, режиму (одиночная / кооператив / мультиплеер).
- Аналитика по рейтингу.

**Приоритеты, заданные преподавателем:**
1. **Задача минимум — очистка и унификация данных** (ETL). Это обязательное ядро проекта.
2. **Вторая техническая задача — рекомендательная система.**
3. Остальное (ML-классификаторы, история рейтинга) — после первых двух.

**Что сознательно убрано из плана:** авторизация, личный кабинет и личные списки игроков, роли куратора и администратора.

## 3. Задача минимум: очистка и унификация (ETL)

Запуск: `python -m app.etl.import_data --source data/steam_games.csv --reviews data/steam_games_reviews.csv`

### Этапы

1. **Извлечение.** Потоковое чтение CSV через pandas chunks или `csv`. Файл 970 МБ целиком в память не грузим.
2. **Валидация.** Каждая строка проходит Pydantic-схему. Отклоняются:
   - пустой app_id или name;
   - некорректная дата;
   - отрицательная цена или отрицательные голоса;
   - дубль app_id.
   Причина отказа пишется в отчёт.
3. **Очистка и унификация:**
   - JSON-строки (genres, categories, tags, developers, publishers, languages) → списки → отдельные таблицы-справочники;
   - справочники нормализуются: регистр, пробелы, синонимы;
   - `estimated_owners` «100000 - 200000» → два числа (min, max);
   - даты приводятся к ISO;
   - цена: число плюс флаг is_free;
   - `user_score` отбрасывается, `metacritic_score = 0` → NULL;
   - языки: убираются HTML-мусор и пометки вида `[b]*[/b]`;
   - платформы: три булевых поля.
4. **Разбор обзоров прессы:**
   - текст делится на цитаты, из каждой выделяется издание и оценка;
   - оценка приводится к шкале 0–100: /5 ×20, /10 ×10, /20 ×5, % и /100 как есть;
   - название издания нормализуется: lower, без пунктуации, словарь синонимов;
   - цитата без оценки сохраняется как текст с `score = NULL`.
5. **Загрузка.** Upsert по `app_id` (`INSERT … ON CONFLICT DO UPDATE`). Повторный запуск не создаёт дублей.
6. **Отчёт о запуске.** Запись в таблицу `etl_runs` и в лог: сколько прочитано, загружено, обновлено и отклонено, с разбивкой по причинам.
7. После загрузки запускается пересчёт рейтинга (раздел 5).

По желанию: плановый запуск через APScheduler или cron.

## 4. Вторая задача: рекомендательная система

Content-based: пользователей и истории покупок в данных нет, поэтому рекомендации строятся по свойствам игр.

### Модель

- Вектор игры: one-hot или TF-IDF по жанрам, категориям и тегам плюс нормализованные год выхода, цена и платформы.
- Сходство — косинусное (`sklearn.metrics.pairwise` или `NearestNeighbors`).
- Итоговый ранг: `сходство × w1 + индекс качества × w2`, чтобы похожие, но слабые игры не выходили наверх.
- Вычисляется офлайн после ETL: топ-K похожих для каждой игры, которая есть в рейтинге. Результат сохраняется в таблицу `game_similarities`.

### Сценарии

- `GET /games/{id}/similar?limit=10` — похожие игры («если понравилась эта»).
- `POST /recommendations` — подбор по анкете: жанры, платформа, язык, режим (кооп / мультиплеер / одиночная), бесплатная или до N рублей, исключить игры из списка. Ответ — лучшие по индексу среди подходящих.
- Холодный старт: если у игры мало голосов, вес сходства выше, вес индекса ниже.

### Оценка качества

Для отчёта: выборочная проверка похожих на известные игры. Метрика — пересечение жанров и тегов у рекомендаций (precision@K по совпадению жанра). Нужно уточнить у преподавателя, какую метрику он ждёт.

## 5. Рейтинг и бизнес-правила

Задание требует не меньше 3 правил вне CRUD. Все правила живут в слое `app/services/`.

1. **Индекс всех времён.** `index = w_c × critic_score + w_p × player_score`.
   - `player_score` — нижняя граница доверительного интервала Уилсона по positive/negative, ×100. Тогда 3 голоса «за» из 3 не обгонят 9 000 из 10 000.
   - Если оценки прессы нет, `index = player_score`, а у игры стоит пометка «только игроки».
2. **Допуск в рейтинг.** Не меньше N голосов игроков, N подбирается по данным. Остальные игры получают статус «недостаточно данных».
3. **Флаг расхождения.** Если `|critic_score − player_score| > X` (X ≈ 20, уточнить по распределению), игра помечается: «переоценена прессой» или «недооценена прессой».
4. **Must play — смена статусов при пересчёте.**
   - Статусы: `candidate → in_list → dropped`.
   - Игра входит в список, если её индекс выше порога P_in. Выбывает, если индекс ниже P_out (P_out < P_in, чтобы не было дребезга).
   - Каждый переход фиксируется с датой.
5. **Атомарный пересчёт.** Новые индексы, флаги, статусы must play и снимок истории пишутся в одной транзакции. Если пересчёт падает, остаётся прошлая версия рейтинга.

## 6. База данных (PostgreSQL)

| Таблица | Назначение | Ключевые ограничения |

| languages, game_languages | языки, M:N | то же |
| developers, game_developers | разработчики, M:N | то же |

| game_scores | текущий индекс, player_score, critic_score, флаги | PK app_id |

## 8. ML-классификаторы (после ETL и рекомендаций)

Блок одобрен преподавателем в формате: предобработка и отбор признаков, train/test, не меньше 2 алгоритмов, выбор по ROC-AUC, сохранение в pkl, эндпоинты `/ml/upload-model`, `/ml/predict`, `/ml/predict-from-csv`.

- **Модель 1 — «потенциальный хит».** Попадёт ли игра в верхние X% по player_score. Обучение на 56 763 играх с ≥10 голосами. Признаки: жанры, теги, категории, цена, год, платформы, число языков, достижения, DLC. Голоса в признаки не входят, иначе цель утечёт.
- **Модель 2 — «пресса оценит ≥75».** Обучение на ~4 700 играх с оценкой прессы. Прогноз для игр без обзоров.
- Алгоритмы: LogisticRegression, RandomForest, GradientBoosting. Сравнение по ROC-AUC.
- Код: `ml/` — ноутбук EDA и скрипт обучения; `app/ml/` — загрузка pkl и прогноз; `models/` — pkl (не в git).
- `/ml/predict-from-csv` принимает сырой или предобработанный CSV и возвращает ROC-AUC, если в файле есть разметка.
- Анализ ведётся на полном датасете.
